# Tabs ’n’ Such

Implementation plan for Ladyflock’s customizable new tab dashboard · `tabs-n-such` · reviewed against `538de0a72a5a`.

A person can open a new tab, keep typing in the address bar, or use the page to resume a tab, start a timer, or pick up a note. The catalog has **30 widgets**. Installing Ladyflock or choosing a preset never subscribes anyone to a service. Two widgets, Feed Reader and Weather, can retrieve information after setup. The other 28 can render and update from local inputs. Following a link, submitting a search, or resuming a download is an explicit browser action that can use the network.

## 1. What opens on a new tab

Use the existing **Settings → Tabs and startup → New tab page** control and URL preference. Keep Blank as the installation and reset default. Offer Dashboard beside it, with a preview that opens the actual local page. This honors the documented empty, focused address field and gives the dashboard a discoverable entry point. [Quiet Design, “New tabs”](Documentation/UI/QuietDesign.md#new-tabs) · [Startup settings](Base/res/ladybird/about-pages/settings/startup.js)

| User choice | Stored `newTabPageURL` | Opening a new tab |
|---|---|---|
| Blank | `about:newtab` | Existing themed static document, including before first paint. No dashboard controller, subscriptions, or database access. |
| Dashboard | `about:dashboard` (proposed Qt application page) | Page title “New Tab”. Focus stays in the empty address field. The dashboard loads its own layout on first use. |
| Custom URL | Existing URL value | Preserve the current navigation and address display rules. Leave pre-existing values, including a user-chosen `about:blank`, intact on upgrade. |

Derive the selector from that single preference. Saving a custom value, switching choices, resetting, restarting and first-run completion must all use the existing setter/observer path. Changing the choice affects subsequently opened tabs. Existing note editors stay open. On a frontend without a dashboard factory, omit Dashboard from the picker and resolve a saved dashboard preference to the themed blank page at launch/new-tab time, without rewriting the preference. A direct visit on such a frontend must also give an intelligible fallback. [Settings](Libraries/LibWebView/Settings.cpp) · [SettingsUI](Libraries/LibWebView/WebUI/SettingsUI.cpp)

Apply the rule to the `+` button, keyboard shortcut, new windows, blank startup and private windows. Preserve first-run, session restore and explicit launch URLs. Audit the configured-new-tab checks for focusing the location editor and replacing an unused tab during restore. Exclude empty dashboard tabs from recently closed units the same way as `about:newtab`. Check that a custom website still displays its origin and that `about:blank` and `about:srcdoc` remain visible even when configured. [Qt startup and recovery](UI/Qt/Application.cpp) · [BrowserWindow](UI/Qt/BrowserWindow.cpp) · [SessionStore](UI/Qt/SessionStore.cpp) · [LocationEdit](UI/Qt/LocationEdit.cpp)

**First dashboard.** Start with World Clock (`3×2`), Quick Tasks (`4×3`) and Scratchpad (`4×3`), in that order. They work before the browser has accumulated any history. Keep Search Box optional because the address field already has focus. In a private or ephemeral session start with Clock and Calculator, with session-only customization. Keep `Customize` reachable when the last card is removed. An empty customized layout is a saved choice and survives a restart in a persistent scope.

### Page identity and lifetime

1. At top-level document commit, bind the dashboard connection to its browser-owned document generation, WebUI ID, view ID, browsing-session ID, identity, persistence policy and frontend profile. Qt resolves the view to its owning tab/window when handling an action, including after a tab moves. A page in window A must keep operating on A when window B gains focus. Reject a missing/detached source. A view can survive navigation, so a view ID alone cannot authorize a late reply. [Canonical document](Libraries/LibWebView/CanonicalDocument.cpp) · [Channel creation](Libraries/LibWebView/WebContentPage.cpp)
2. Add the exact dashboard URL to the internal URL list for the intended scripting and secure-context behavior. That list also affects site scripting policy. Review both callers, keep the exact match and test with page JavaScript disabled. Only the live top-level dashboard channel may use these operations. A regular document, an embedded copy, a `resource:` URL and another about page get no dashboard authority. [Internal URLs](Libraries/LibURL/InternalURLs.h) · [Script policy](Libraries/LibWeb/HTML/Scripting/Environments.cpp) · [Secure contexts](Libraries/LibWebCommon/SecureContexts/AbstractOperations.cpp)
3. Define a finite set of typed requests. For example, `tabs.focus` takes an opaque target handle returned to that page. Browser-owned code re-resolves it, checks caller scope and current target state, then consumes one transient activation for the focus action. Use the same pattern for navigation, restores, media commands, setting changes and native dialogs. Ordinary reads and debounced saves of the user’s own text use scoped authorization without consuming clicks. Never accept renderer-supplied identity, profile path, window ownership or a claim of user activation. [WebUIPage activation](UI/Qt/WebUIPage.cpp)
4. Replies carry the originating request ID and document binding. Return explicit outcomes for success, validation failure, conflict, stale target, unavailable capability and storage failure. On navigation, close, identity change, Hub disconnect or purge, revoke page handles, detach observers and cancel pending work. Discard late replies, including a native file picker completing after the page closed. Reconnect from a fresh authorized snapshot. Do this for the split Hub and the in-process build.
5. Treat names, titles, URLs, excerpts and filenames as data. Use text nodes and validated link destinations. External links accept HTTP(S) under normal navigation policy, tool links use a small compiled list of supported about pages, and local-file actions accept an opaque user-picked handle. Load only packaged scripts/styles and bounded locally cached icons. Enforce and verify a dashboard document policy that blocks direct network loads, remote images, frames, forms and connections. If a resource or feature is unsupported, show a working text/icon fallback in that card.

### Data scope

The browser selects scope before a store is opened, a subscription is attached, or a response is serialized. The same check applies to pushes and actions. Hiding a card after sending its data would disclose the data. [BrowsingSession](Libraries/LibWebView/BrowsingSession.h) · [Identity lifecycle](Libraries/LibWebView/IdentityManager.h)

| Context | Layout and personal widget data | Browser-derived cards and network |
|---|---|---|
| Persistent default identity | Profile-local layout, shared collections and per-instance configuration. | Use only data attributable to this scope. Profile-wide bookmarks and add-ons are available here. Network cards require separate consent. |
| Persistent named identity | Separate layout, notes, timers, settings, consent and cache keyed by that identity. Enable disk persistence only when its dashboard rows participate in identity purge, including interrupted-purge recovery. Until then use session memory and identify it as temporary. | Allow session-scoped sources. Hide profile-global bookmarks/add-ons and any record with ambiguous provenance. Honor the identity’s history and network policies independently. |
| Private, disposable, temporary identity or temporary profile | Fresh in-memory namespace for the live session. User-created tasks, notes, pins, layouts and edits work within it. Destroy the namespace with that session. Do not open a regular dashboard database, import its layout or restore its undo stack. | Offer local utilities. Allow live tabs/media and redacted policy only when ownership is proven. Suppress history, closed units, regular bookmarks, downloads, add-on inventory, permission origins, external fetches and regular pinned files. Use built-in tool links and shortcuts. |
| SQL disabled or persistent store unavailable | Show a session-only layout with a visible save-status explanation when editing. On a mid-session write failure keep the draft available and offer retry. | Apply the same source authorization. Cancel network consent that cannot be recovered or validated. |

History widgets use `Application::history_store_for_identity` and the session’s `persists_history()` policy. Gate recently closed items and downloads on provenance at the owning store. `RecentlyClosedSessionUnit` does not identify the browsing identity of each member, and `DownloadsPage` currently filters by a Boolean. Add attribution for new records before exposing them on the dashboard. Older or mixed units of uncertain ownership stay unavailable there. Check every member of a closed window before offering restore. [Session units](UI/Qt/SessionStore.h) · [Download filtering](UI/Qt/DownloadsPage.cpp)

## 3. Storage, editing and recovery

Use one dedicated `LibDatabase` store under the frontend profile’s data directory, opened lazily by Qt for eligible persistent scopes. Follow the migration preflight and fallback in `Application::create_history_store`. Use the database library’s versioned migration and error-returning transaction API. An unreadable, corrupt or newer database must be preserved for recovery. Open an independent memory store for that session and surface its save status. [Database API](Libraries/LibDatabase/Database.h) · [Qt store creation](UI/Qt/Application.cpp)

| Proposed record | Key and invariant |
|---|---|
| Layout metadata | Scope key and layout revision. Distinguish “never initialized” from “saved empty”. Keep density/compact preference here. |
| Card instance | Scope and stable instance ID, widget type, versioned configuration. Browser assigns and validates IDs. Allow multiple Bookmark Shelves, clocks, scratchpads, weather locations and filtered task lists. Default to one instance for every other type. |
| Placement | Scope, breakpoint and instance ID. Integer column, row, width and height. Enforce bounds and uniqueness. Validate the complete set for overlaps before writing. |
| Personal item | Scope, collection, item ID, item revision and versioned value. Tasks, reading items, habits, timer and snippets have shared collections. Shelves and clocks keep instance settings. Notes have independent IDs so a layout operation cannot erase the only copy of a note. |
| Network grant/cache | Scope and normalized source ID, consent version, expiry and last successful update. Keep grants outside presets, undo and UI-provided configuration. Revalidate them at use. |

**Commit protocol.** A layout command includes a unique operation ID and expected layout revision. Apply membership, affected placements and revision in one transaction, acknowledge after commit, then broadcast the new revision to other pages in the same scope. Duplicate deliveries of a committed command return its prior result within the retry window. After reconnect or an unknown outcome, reload and reconcile before retrying. A stale revision returns the latest snapshot. Do not replay a whole stale grid over a concurrent edit. A missed patch or revision gap triggers a snapshot refresh. Use bounded strings, arrays and payloads before allocating or persisting. Limit each snapshot to the visible page of results, bound per-card and per-scope stored bytes and item counts, and present a recoverable quota error. Never silently evict user-authored text to make room for service caches. Initial design limits are 60 cards per layout, 512 grid rows, 64 KiB per note, and 1 MiB per codec input. Show limits before a write and keep the previous saved value on failure.

**Concurrent text edits.** Debounce per item. Keep the current draft and show `Saving`, `Saved`, `Session only` or `Couldn’t save` from the actual outcome. Compare the note revision at save. If another page edited the same note, preserve both texts and let the user save the local one as a copy or load the current version. Flush pending edits on normal close using the browser’s close flow. If flushing fails, offer a way to keep/copy the draft. Recovery after a crash promises only the last acknowledged revision.

**Remove, reset and undo.** Removing a card detaches its presentation. Shared lists and named notes stay available when the card is re-added. Include an explicit way to reopen an existing note, plus a separate delete-data action with a named target. Preset switching replaces placements and card configuration in a single transaction after showing what changes. Preserve detached references to user-authored data and offer the data again when that type is re-added. Retain personal collections. Keep up to 30 acknowledged layout operations per editing page, with inverse data for removed instances and their placement/configuration. Invalidate an undo/redo entry when a newer edit conflicts with it. Undo never reopens a tab, reverses a permission change, deletes text written elsewhere or restores network consent. Removing the last consumer of a feed or location revokes its grant, cancels refresh and clears its cache. Provide a scoped `Delete dashboard data` action, and integrate identity/profile removal. History-derived cards reread their owner on history clearing and keep no shadow history in the dashboard store.

## 4. Card layout and interaction

Reuse the page, card, control, separator and focus tokens from [ladybird.css](Base/res/ladybird/ladybird.css) and the card/menu styles from [webui.css](Base/res/ladybird/about-pages/webui.css). Scope the dashboard’s wider content area so the common 800 px body rule and generic `header` selector do not also size every card header. Grid max width is 1280 CSS px. Use `--page` for the canvas, `--surface` or `--tile` for cards, `--separator` for edges, and the existing focus-edge/ring pair. Use private chrome to indicate the window context and a text cue for session-only edits. Respect the selected appearance, visible focus and reduced motion. Give actions accessible names, render status with text or a glyph as well as color, and reserve shadows for the current drag or open menu.

A card is a labelled section with a heading, body and menu. Its compact view must fit a usable primary action. Additional rows can scroll inside the card or open a detail view. Controls stay reachable on keyboard focus and touch. Use a compact presentation based on actual card width and height, including zoom and long labels. `Customize` follows the grid in reading order and must not cover the last card or an onscreen keyboard. A module that fails to load, rejects an async update, or receives malformed data shows Retry/Remove in its own card. Other cards and `Customize` keep working.

| Available grid width after page padding | Columns | Nominal row height / gap |
|---|---:|---|
| 1120 px and above | 12 | 96 / 14 px |
| 800–1119 px | 8 | 96 / 12 px |
| 520–799 px | 4 | 92 / 12 px |
| Below 520 px | 2 | 88 / 10 px |

**Placement.** The catalog below defines three supported sizes per card in `compact / default / expanded` order on the 12-column grid. At a smaller breakpoint cap each width at the column count, deduplicate identical sizes and keep the height. Use a full-width compact list/detail view when controls would otherwise clip. Each breakpoint may have its own saved placements for the same card IDs. On first display at a new breakpoint, project the wide layout in `(row, column, instance ID)` order to the first free slot in row-major order. Derive the wide layout from the starter preset if necessary. Resizing the viewport alone performs zero writes. The first explicit edit at that breakpoint saves its projection. Create the canonical wide placements with the first saved edit, even if it occurs on a narrow window. Use the current membership when deriving any later layout. Adding places a card in the first free slot in other saved layouts. Removal applies everywhere. Catalog replacement reuses the prior anchor where it fits at each saved width. A narrow edit can never reconstruct or overwrite an existing wide layout by scaling coordinates.

**Move and resize.** In edit mode only the grip or resize handle starts a drag, after 4 CSS px of movement. Leave buttons, links, text selection and nested lists usable. Snap a resize to the closest valid preset, ordered by width difference, height difference, then catalog order. Use logical inline coordinates in RTL. Calculate previews from the pre-gesture snapshot at most once per animation frame. Pin the active target, clamp it inside the grid, then place remaining rectangles in their previous stable reading order at their prior column, shifting downward to the first nonoverlapping row at or below their prior row. Optional compact mode then moves nonactive cards upward into legal gaps in the same order. Reject an operation that exceeds the row limit. The solver must terminate, yield the same output for the same input and be idempotent on its resolved layout. Commit once on drop. Escape, pointer cancellation, loss of capture or a breakpoint change cancels the preview without a write.

**Swap and replace.** `Swap positions…` selects a second placed card. Same-size cards exchange coordinates exactly. For unequal sizes, preview both anchors, retain each card’s size and reject an exchange if the two pinned rectangles overlap or cross a boundary. Displace other cards with the normal solver. Dragging can invoke the same explicit swap mode. `Replace widget…` opens the catalog and shows the nearest supported size before commit. A replacement gets a fresh instance ID and its own configuration. Disable already-placed singletons as replacements and offer the separate position swap. A preview must match the eventual commit at the same revision.

**Keyboard, pointer and focus.** `Customize` enters edit mode. Each card’s menu offers Move to cell, Swap positions, Resize, Replace, Configure and Remove as applicable. Move to cell uses a row/column choice with Apply, so a tap-only user can reach empty cells as well as occupied rows. Use the same command paths for arrow-key movement, Shift+Arrow resize and the menus. Bind edit shortcuts only on the focused card handle. Preserve native editing and undo in text inputs, notes and the calendar. Escape closes the innermost popup or cancels a gesture first. Restore focus to the invoking card, its replacement, the next card after removal, or `Customize` on an empty grid. Keep DOM order aligned with the resolved visual reading order after commit. Announce the new position or size once per command. A pointer-only route without dragging is an explicit acceptance check. [W3C guidance on dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

## 6. Network features

Feed Reader and Weather are the only cards with service requests. A monitor for user-entered LAN/localhost endpoints would give a new-tab page a privileged route into local services. The URL Inspector fills that catalog slot while keeping its input private. An empty network card explains what setup would disclose. Adding a card, applying a preset, opening the picker or previewing it must make **zero** requests, including DNS. A provider can see the request and the connection’s egress address even without cookies.

- **Consent and scheduling.** On a user gesture, register a specific feed or a weather provider/location. Display the destination, transmitted fields and refresh behavior. Manual refresh is the initial default. A separate switch enables refresh while visible, at most once per source per 30 minutes. Deduplicate identical sources within a scope across tabs, back off on failure and honor a longer retry interval. A completed response reports the time of the successful fetch. Stop scheduling when the last subscriber hides or goes away. Disabling the source or network policy cancels work already in flight and invalidates late results.
- **Request ownership.** The renderer requests a refresh by its scoped grant ID. The Hub checks current consent with the owner, document/session binding, visibility for scheduled refreshes, current policy epoch, background-service policy where applicable, proxy/DNS rules and available route. Use that session’s RequestServer. A routed identity can never fall back to a direct connection. Recheck on policy change, source removal and before cache commit. No cookies, HTTP authentication, client certificate prompts, referrer, shared browser cache, persistent credentials or ambient service worker state. Make transport enforcement a prerequisite for offering either widget.
- **Destinations and bounds.** Use public HTTPS endpoints. Deny embedded credentials, nonpublic/local destinations and unsafe resolution changes at the point that establishes the connection. Reject redirects in the first implementation, including redirects to another HTTPS host. If the required target restrictions cannot be enforced through the configured proxy or resolver, disable refresh for that route. Bound a fetch to a 10-second deadline, 1 MiB decoded body, 20 items per feed, two concurrent requests per scope and a 5 MiB scoped cache with expiry/eviction. Reject an over-limit stream during decoding. Parse XML without external entities, DTD loading or subresources. Treat feed links as ordinary user-initiated navigation. Render summaries as text.
- **Provider and retention.** Before enabling Weather, choose an endpoint with a documented response schema, attribution, redistribution/usage terms and rate limit suitable for Ladyflock. Ship only the fixed adapter and its required attribution. Round coordinates to a disclosed precision, validate ranges, and include units/version in cache keys if the stored response differs. Clear cached data and grants on source deletion, consent withdrawal, scope purge or `Delete dashboard data`. No network cards or cached previews in private/ephemeral sessions.

Use synthetic feed/weather responses, an instrumented resolver/transport and isolated proxy-policy fixtures. Count attempted DNS and network dispatch as well as completed requests. Exercise offline startup, unavailable proxy, policy tightening mid-request, revocation, oversized responses, malformed XML/JSON and two visible tabs sharing one fetch. Do not require a public service in CI.
